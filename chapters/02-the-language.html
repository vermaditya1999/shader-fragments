The language: numbers, vectors, functions

GLSL is a small language, and you can learn nearly all of it in one sitting. It's strict in a few places where JavaScript is relaxed, and those few places cause most beginner errors, so this chapter goes through them carefully. Everything here is also in the reference, and you can hover any word in the workbench to see what it means.

2.1Instructions, semicolons and comments

A shader is a list of instructions, called statements, run from top to bottom. Each one ends with a semicolon. Spaces and line breaks don't matter to the computer, so you can lay code out however reads best.

float a = 1.0;      // a statement, ended by ;
float b = a + 2.0;  // another one

/* A comment can also span
   several lines like this. */

Two more rules: GLSL is case-sensitive (iTime works, itime is an unknown name), and code runs top to bottom, so you have to create something before you use it.

2.2Variables have types

A variable is a named box that holds a value. In GLSL, you must say what kind of value the box holds, called its type, when you create it:

float brightness = 0.75;   // type, name, =, value, ;
int count = 3;
bool isInside = true;

The three basic types:

typeholdsexamples
floata number with a fractional part (“floating point”)0.5, 3.0, -0.25
inta whole number (an “integer”)0, 7, -3
booltrue or false (a “boolean”)true, false, x > 0.5

Once a variable is created, its type never changes. You can change its value, as long as the new value has the same type:

float x = 0.5;
x = x * 2.0;     // fine: x is now 1.0. No type in front, because x already exists.
float x = 3.0;   // error: "redefinition". x already exists in this block.

Names can contain letters, digits and underscores, but can't start with a digit. A few ordinary-looking words are reserved in GLSL and can't be used as names: smooth, flat, sample, filter, input, output, half, among others. If you get a strange error on a line that looks fine, a reserved name is a likely cause.

Add const in front for values that never change, which also documents your intent: const float PI = 3.14159265;.

2.3Whole numbers and decimals: the 1.0 rule

This is the rule that trips up everyone coming from JavaScript. In JavaScript, 1 and 1.0 are the same number. In GLSL, 1 is an int and 1.0 is a float, and GLSL will not convert one into the other for you:

float a = 1;           // error: cannot convert from 'const int' to 'float'
float b = 1.0;         // fine
float c = 2.0 * 3;     // error: float times int
float d = 2.0 * 3.0;   // fine

So write the decimal point every time you mean a float, even for whole numbers. 1. also works, but 1.0 is easier to read.

When you do need to convert, do it out loud: float(i) turns an int into a float, and int(x) turns a float into an int by dropping the fraction (2.9 becomes 2). Here's an example that uses both. Watch out: integer division

Dividing two ints gives an int, and the fraction is thrown away: 7 / 2 is 3, and 1 / 2 is 0. If a value is mysteriously zero, look for an int division.

2.4Arithmetic

The four operators + - * / work as usual. Multiplication and division happen before addition and subtraction, so 1.0 + 2.0 * 3.0 is 7.0. Use parentheses whenever you want a different order, or just to make the order obvious.

There are short forms for updating a variable: x += 0.5 means x = x + 0.5, and likewise -=, *= and /=. i++ adds 1 and i-- subtracts 1.

Adding moves a ramp; multiplying changes its steepness. You'll use those two moves constantly. (The if lines are explained at the end of this chapter.)

2.5Vectors: numbers that travel together

Many values in graphics come in groups: a position has an x and a y, a color has a red, a green and a blue. GLSL bundles them into vectors, and treats each bundle as a single value:

typeholdstypical use
vec22 floatsa position on the screen: (x, y)
vec33 floatsa color (r, g, b), or a point in 3D (x, y, z)
vec44 floatsa color with alpha: the type of fragColor

You make a vector by writing its type like a function, with the parts inside. The parts have to add up to the right count, and you can build bigger vectors out of smaller ones:

vec3 orange = vec3(1.0, 0.5, 0.0);   // three numbers
vec3 grey   = vec3(0.5);             // one number fills all three: (0.5, 0.5, 0.5)
vec2 p      = vec2(0.2, 0.7);
vec3 q      = vec3(p, 1.0);          // a vec2 plus a float: (0.2, 0.7, 1.0)
vec4 c      = vec4(orange, 1.0);     // a vec3 plus a float: a full color
vec3 bad    = vec3(1.0, 0.5);        // error: two values for three slots

2.6Reading parts: .x, .rgb and swizzling

To read one part of a vector, put a dot and its name after it. The parts have three sets of names, and you can use whichever reads best:

slot1st2nd3rd4thuse for
position names.x.y.z.wpoints and directions
color names.r.g.b.acolors
texture names.s.t.p.qrarely used

col.r and col.x are the same slot. Here's the useful part: you can name several slots at once, in any order, even repeating them, and get a new vector back. This is called swizzling:

vec3 col = vec3(1.0, 0.5, 0.2);
col.bgr    // (0.2, 0.5, 1.0): reversed
col.rr     // (1.0, 1.0): a vec2 made of red twice
col.xy     // (1.0, 0.5): the first two
uv.yx      // swap x and y
col.rg = vec2(0.0);   // you can also assign through a swizzle

2.7Math on vectors happens part by part

When you add, subtract, multiply or divide two vectors of the same size, GLSL does it slot by slot:

vec2(1.0, 2.0) + vec2(3.0, 4.0) = vec2(1.0 + 3.0, 2.0 + 4.0) = vec2(4.0, 6.0) vec3(1.0, 0.5, 0.2) * vec3(0.5, 1.0, 0.0) = vec3(0.5, 0.5, 0.0)

When you combine a vector with a single float, the float applies to every slot: vec3(0.2, 0.4, 0.6) * 2.0 is vec3(0.4, 0.8, 1.2). That's how you brighten or darken a whole color at once.

Multiplying two colors slot by slot is exactly what a colored filter does to light. White light through blue glass: each channel of the light is multiplied by how much of that channel the glass lets through.

Two different multiplications

Slot-by-slot multiplication is not the “dot product” from math class, which multiplies the slots and then adds them up into a single number. GLSL has a function for that, dot(), and Chapter 7 explains why it's so useful.

2.8Writing your own functions

A function is a named recipe you can reuse. You've already written one, mainImage. Here's the general shape:

returnType name(type param1, type param2) {
    // ... work ...
    return someValue;   // must match returnType
}

Some rules worth knowing:

  • Define before use. A function must appear above the code that calls it. That's why helper functions sit above mainImage.
  • Parameters are copies. By default a parameter is in: the function gets its own copy, so changing it inside the function doesn't affect the caller.
  • out and inout. An out parameter is an extra output that the function fills in, which is how mainImage hands back fragColor. An inout parameter is read and changed, and the caller sees the change.
  • Same name, different types. You may write several functions with the same name if their parameter types differ. GLSL picks the right one. Many built-ins work this way, which is why abs accepts a float or any vector.
  • No recursion. A function can't call itself. Loops do that job instead.

The line cold + (hot - cold) * t is so useful that GLSL has a built-in for it, mix(cold, hot, t). Chapter 4 explains why it works.

2.9Built-in functions

GLSL comes with about 50 built-in functions: math like sin and sqrt, shaping tools like clamp and smoothstep, geometry like length and dot. You'll meet each one when it's needed, with a picture of what it does. Two things are true of almost all of them:

  • They work slot by slot on vectors: abs(vec2(-1.0, 2.0)) is vec2(1.0, 2.0).
  • They expect floats, not ints: sin(1) is an error, sin(1.0) works.

The reference lists every built-in this course uses. In the workbench, click on a function name (or hover it) and its explanation appears above the code.

2.10Making decisions and repeating

if runs code only when a condition is true. Conditions are comparisons like x > 0.5 or column == 1.0 (two equals signs means “is equal to”), combined with && (and), || (or) and ! (not):

if (x > 0.5 && y < 0.2) {
    col = vec3(1.0);
} else {
    col = vec3(0.0);
}

For picking between two values there's a one-line form, the ternary: condition ? valueIfTrue : valueIfFalse, as in vec3 col = x > 0.5 ? vec3(1.0) : vec3(0.0);.

Loops and branches on a GPU

Because every pixel runs its own copy, a loop of 100 rounds costs 100 times as much on every pixel. Keep loops short and give them a fixed limit. Branches (if) are fine, but when neighbouring pixels take different branches, the GPU often runs both sides for the whole group. Chapter 17 explains why. Many shader writers prefer math tricks like step() over if for small choices, and you'll see why that's natural in Chapter 4.

What you now know

  • Statements end with ;. Names are case-sensitive, and some words are reserved.
  • Every variable has a type: float, int, bool, or a vector.
  • Write 1.0, not 1, for floats. Convert explicitly with float() and int().
  • Vectors bundle 2, 3 or 4 floats. Build them with vec3(…); read parts with .x or .r; reorder them with swizzles like .bgr.
  • Math on vectors works slot by slot, and a float applies to every slot.
  • Functions go above the code that uses them, and parameters are copies unless marked out or inout.
  • if, ? : and for work much like JavaScript, but every pixel runs its own copy.
Exercises: fix the bug

Each snippet has one mistake. Paste it into the workbench (replacing the body of mainImage), read the error, and fix it.

1.

float x = fragCoord.x / iResolution.x;
float steep = x * 2;
fragColor = vec4(steep, 0.0, 0.0, 1.0);
Answer

x * 2 multiplies a float by an int. Write x * 2.0. (One exception to the rule: inside a constructor like vec4(x, 0, 0, 1), GLSL does convert ints for you. Everywhere else it doesn't, so writing .0 every time is the simplest habit.)

2.

vec2 uv = fragCoord / iResolution.xy;
fragColor = vec4(uv, 1.0);
Answer

A vec2 plus one float makes three values, but vec4 needs four: vec4(uv, 0.0, 1.0).

3.

vec2 uv = fragCoord / iResolution.xy;
float smooth = uv.x * uv.y;
fragColor = vec4(vec3(smooth), 1.0);
Answer

smooth is a reserved word in GLSL. Rename it, for example to v.

4. Write a function float brighten(float v) that returns v times 1.5, and use it on the red channel of a ramp.

Solution
float brighten(float v) {
    return v * 1.5;
}

void mainImage(out vec4 fragColor, in vec2 fragCoord) {
    float x = fragCoord.x / iResolution.x;
    fragColor = vec4(brighten(x), 0.0, 0.0, 1.0);
}
