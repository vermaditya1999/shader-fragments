Shaping functions: drawing with math

Almost every visual effect is a curve in disguise: a soft edge is a curve that rises quickly, a stripe is a curve that repeats, a glow is a curve that falls away. This chapter builds a little function plotter out of a shader, then uses it to meet the built-in shaping functions one at a time, each with its picture and its formula.

4.1Functions as machines

In math, a function is a machine: a number goes in, a number comes out, and the same input always gives the same output. We write y = f(x): put x in, get y out. A shader's mainImage is a function too, just a bigger one: position in, color out.

Math from zero: the graph of a function

To see a function at a glance, draw its graph. For each x along the horizontal axis, go up to the height f(x) and put a dot there. Join the dots and you have a curve whose shape tells you how the function behaves: where it rises, where it's flat, where it jumps.

For example, for f(x) = x × x: at x = 0 the dot is at height 0, at x = 0.5 at height 0.25, at x = 1 at height 1. The curve starts flat and bends upward.

4.2Drawing a graph in a shader

In p5 you'd draw a graph by looping over x and drawing line segments. A shader can't draw lines, so turn the question around, as always: each pixel asks “is my y close to f(my x)?” If yes, it lights up. Together, the lit pixels trace the curve.

4.3Straight lines: slope and offset

return x; draws a diagonal: output equals input. Two moves change it, the same two from the ramps in Chapter 2:

  • Multiply to change the steepness, called the slope: 2.0 * x rises twice as fast; 0.5 * x half as fast; -x goes down.
  • Add to slide the line up or down, called the offset: x + 0.2 is the same line, 0.2 higher.

Any straight line can be written as y = a·x + b, with slope a and offset b. Remapping a range (Chapter 3) is just picking the a and b that send your start and end where you want them.

4.4Curves: powers and roots

Multiplying x by itself bends the line. Inside 0..1 this is especially useful, because a number between 0 and 1 gets smaller when you multiply it by itself: 0.5 × 0.5 = 0.25. So x * x starts slowly and speeds up, while both ends stay put, because 0 × 0 = 0 and 1 × 1 = 1.

Math from zero: powers

x² (“x squared”) is x × x. x³ is x × x × x. In GLSL, pow(x, 2.0) means x², and the power doesn't have to be a whole number: pow(x, 0.5) is the square root, √x, the number that gives x when multiplied by itself (√0.25 = 0.5).

On 0..1, powers above 1 sag below the diagonal (slow start, fast finish) and powers below 1 bulge above it (fast start, slow finish). Animators call these curves easing.

Notice that the curve vanishes to the left of 0. pow is undefined for negative numbers: the GPU returns garbage, usually NaN (“not a number”), and NaN never counts as “close to the curve”. x * x doesn't have this problem, so for squares and cubes prefer plain multiplication. This is your first taste of a theme from Chapter 19: when part of a picture mysteriously disappears, look for undefined math.

4.5step: a hard switch

step(edge, x) is the simplest decision there is. It returns 0.0 when x is below the edge and 1.0 once x reaches it:

step(edge, x) = x < edge ? 0.0 : 1.0

Watch the argument order: the edge comes first, then the value. step replaces many small if statements with math, which GPUs like, and it gives you a number you can multiply with: col * step(0.5, uv.x) keeps the color only on the right half. Two useful variations: 1.0 - step(e, x) flips it (1 below the edge), and step(a, x) - step(b, x) is 1 only between a and b.

4.6smoothstep: a soft switch

A hard switch gives hard, jagged edges. smoothstep(edge0, edge1, x) is a switch that takes its time: 0 below edge0, 1 above edge1, and a smooth S-shaped ramp in between.

Math from zero: where the S-curve comes from

smoothstep works in two stages. First it rescales x so that edge0 becomes 0 and edge1 becomes 1, and clamps anything outside: t = clamp((x - edge0) / (edge1 - edge0), 0.0, 1.0). That's a straight ramp. Then it bends the ramp with a curve:

smoothstep = t * t * (3.0 - 2.0 * t) (that's 3t² − 2t³)

Why that curve? We want something that goes from 0 to 1 like the ramp, but starts and ends flat, so it joins the flat parts outside the edges without a kink. The simplest polynomial that is 0 at t = 0, 1 at t = 1, and flat at both ends is exactly 3t² − 2t³. You can check two of those: at t = 0 it's 0, and at t = 1 it's 3 − 2 = 1. That flatness is why smoothstep looks so natural, and you'll meet this same curve again inside noise in Chapter 11.

Its most important use is soft edges. When edge0 and edge1 are very close together, about one pixel apart, smoothstep is an almost-hard switch whose tiny ramp hides the jagged staircase of pixels. Compare a hard edge with a soft one:

Here the soft ramp is deliberately wide so you can see it. Make the 0.15s small, like 0.005, and you get an edge that looks crisp but not jagged. Chapter 8 shows how to make it exactly one pixel wide.

Watch out: edge order

The GLSL specification says smoothstep's result is undefined when edge0 is not smaller than edge1. Many GPUs happen to give a flipped curve for smoothstep(0.8, 0.2, x), but some don't. To go from 1 down to 0, write 1.0 - smoothstep(0.2, 0.8, x) instead.

4.7Limiting values: min, max, clamp, abs

  • min(a, b) returns whichever is smaller, so min(x, 0.7) follows x until 0.7 and then stays there: a ceiling.
  • max(a, b) returns the larger, so max(x, 0.2) is a floor at 0.2.
  • clamp(x, lo, hi) does both: min(max(x, lo), hi). clamp(x, 0.0, 1.0) is the classic way to make a value safe for a color.
  • abs(x), the absolute value, drops the minus sign: abs(-0.3) = 0.3. Its graph is a V. It answers “how far is x from 0, in either direction?”, which makes it the key to symmetry (Chapter 10) and to outlines (Chapter 8).

4.8Staircases and saws: floor, fract, mod

These three are the engine of every repeating pattern in the course.

  • floor(x) rounds down to a whole number: floor(2.7) = 2.0, floor(-0.3) = -1.0. Its graph is a staircase. ceil rounds up, round to the nearest.
  • fract(x) keeps only the part after the decimal point: fract(2.7) = 0.7. It's exactly x - floor(x), so it always lies between 0 and 1. Its graph is a sawtooth: it climbs from 0 to 1, drops back to 0, and climbs again, forever.
  • mod(x, m) is the remainder after dividing by m: x - m * floor(x / m). It's a sawtooth from 0 to m instead of 0 to 1. fract(x) is the same as mod(x, 1.0).

Here's why fract matters so much: whatever you draw using fract(x * 3.0) instead of x gets drawn three times, because the input runs from 0 to 1 three times. Feed it to step and you get stripes: step(0.5, fract(x * 3.0)). Do it to x and y together and you get a grid. That's all of Chapter 10 in one sentence.

A neat variation: abs(fract(x) - 0.5) turns the saw into a triangle wave, which goes up and down smoothly without the sudden drop. Its value is the distance to the nearest half-integer, and the grid lines in the plotter use exactly this trick.

4.9Sliding between values: mix

You've used mix in every plotter above. mix(a, b, t) slides from a to b as t goes from 0 to 1. It's called linear interpolation (often shortened to “lerp”).

Math from zero: linear interpolation

To get from a to b you have to travel a distance of b − a. Travel a fraction t of that distance, starting at a:

mix(a, b, t) = a + (b - a) * t

At t = 0 you're still at a. At t = 1 you've traveled the whole way: a + b − a = b. At t = 0.5 you're halfway. The same formula is sometimes written a × (1 − t) + b × t, which says “a little less of a, a little more of b”. They're equal; multiply out the brackets to check.

Because vector math works slot by slot, mix works on colors too, which makes it the standard way to build gradients:

Both halves blend the same two colors. On the right, smoothstep reshapes t so the blend happens in a narrower band with soft ends. Shaping the t of a mix is how you control where a gradient happens.

4.10Combining functions: bumps, pulses and falloffs

Functions are building blocks. You can add them, subtract them, and feed one into another:

  • A plateau: rise with one smoothstep, fall with another: smoothstep(0.2, 0.3, x) - smoothstep(0.6, 0.7, x). 1 in the middle, 0 outside, soft shoulders.
  • Nesting: f(g(x)). For instance smoothstep(0.0, 1.0, fract(x * 4.0)) is a repeating soft ramp.
  • Exponential falloff: exp(-x * k) starts at 1 and fades toward 0, faster for bigger k. It's how light fades in fog (Chapter 14).
  • Inverse falloff: 0.05 / x is huge near 0 and fades quickly. It's how a glow looks (Chapter 8).

Every visual effect is a curve. If you can plot a function, you can paint with it: feed it a coordinate, and use what comes out as a brightness, a mix amount, a size or a position.

What you now know

  • A shader can draw a graph by asking each pixel whether its y is close to f(its x).
  • Multiplying changes slope, adding changes offset; powers bend a 0..1 ramp into easing curves.
  • step(edge, x) is a hard switch; smoothstep(e0, e1, x) a soft one, using 3t² − 2t³.
  • min, max, clamp limit values; abs folds negatives and measures distance from 0.
  • floor makes staircases, fract and mod make sawtooths, the engine of repetition.
  • mix(a, b, t) = a + (b − a) × t slides between numbers or colors.
  • Functions combine: subtract smoothsteps for a plateau, nest them, use exp(-x) or 1/x for falloffs.
Exercises

1. In the plotter, draw a curve that is 0 until x = 0.3, rises smoothly to 1 at x = 0.5, and stays at 1.

Solution
return smoothstep(0.3, 0.5, x);

2. Draw a triangle wave that repeats 4 times between 0 and 1 and goes from 0 to 1 and back.

Hint

abs(fract(x) - 0.5) goes from 0.5 down to 0 and back up. Multiply by 2 to make it reach 1, and feed it x * 4.0.

Solution
return abs(fract(x * 4.0) - 0.5) * 2.0;

3. Paint the canvas with five vertical stripes whose edges are soft rather than hard.

Solution
vec2 uv = fragCoord / iResolution.xy;
float s = smoothstep(0.4, 0.6, abs(fract(uv.x * 5.0) - 0.5) * 2.0);
fragColor = vec4(vec3(s), 1.0);
