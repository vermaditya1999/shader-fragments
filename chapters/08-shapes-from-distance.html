Shapes from distance

So far, every shape has been a yes-or-no question: is this pixel inside? This chapter asks a better question: how far is this pixel from the edge? That single number gives you smooth edges, outlines, glows and rounded corners for free, lets shapes melt into each other like clay, and is exactly how the 3D worlds in Part II are built.

8.1The problem with yes or no

A pixel isn't a point. It's a small square, and a shape's edge usually cuts through some pixels partway. But a yes/no test only checks each pixel's center, so a pixel is either fully colored or not at all. Along a curved or slanted edge, that produces a staircase called aliasing (or "the jaggies").

On a high-resolution screen the steps are tiny, so this example magnifies them: it treats every 10 × 10 block of real pixels as one big pixel. The left circle uses yes/no. The right one uses distance to estimate how much of each pixel the shape covers:

Here's the reasoning behind the right-hand formula. Zoomed in to the size of one pixel, any smooth edge looks like a straight line. If the edge passes exactly through the pixel's center (d = 0), about half the pixel is covered. If the center is half a pixel inside (d = −px/2), the whole pixel is covered; half a pixel outside, none of it. In between, coverage changes in a straight line with d. That's clamp(0.5 - d / px, 0.0, 1.0): distance, measured in pixels, turned into coverage. This is anti-aliasing, and it needs a distance, which a yes/no test can't give you.

Most shader code writes the same idea with smoothstep, fading over a couple of pixels with a gentle curve. This course uses that form from now on:

float px = 2.0 / iResolution.y;              // the size of one pixel in uv units
float fill = 1.0 - smoothstep(-px, px, d);   // 1 inside, 0 outside, smooth across the edge

8.2Signed distance

The d above has a sign that carries information:

  • positive outside the shape: how far you'd have to travel to reach it,
  • zero exactly on the edge,
  • negative inside: how deep you are, that is, how far to the nearest way out.

A function that returns this for every point is a signed distance function, or SDF. For a circle of radius r centered at the origin, it's the distance to the center minus the radius:

float sdCircle(vec2 p, float r) {
    return length(p) - r;
}

An SDF doesn't only describe the edge. It gives a number for every point on the canvas, called a distance field. Coloring the field directly shows it: here, orange is outside, blue is inside, each band is 0.05 units of distance, and the white line is where the distance is zero:

Each band is one more step of 0.05 away from the edge, so you can read distances by counting bands. Notice that the field exists everywhere, even far from the circle: every pixel knows exactly how far it is from the edge.

8.3What a distance gives you for free

With a distance in hand, many effects are one line each. All four panels below use the same circle SDF:

  • Fill: d < 0, with a smooth edge.
  • Outline: abs(d) is the unsigned distance to the edge, so abs(d) - t < 0 is a band of thickness 2t centered on the edge. It works for any shape.
  • Glow: k / abs(d) is huge near the edge and fades with distance, like light spreading from a neon tube. Add it on top (light adds, Chapter 6).
  • Ripples: fract(d * n) repeats along the distance, so the copies follow the shape's outline. Subtracting time makes them travel.

Two more one-liners worth remembering. d - r grows a shape outward by r, rounding its corners as it goes (you'll see it on the box below). And abs(d) - t turns any shape into a hollow shell of thickness 2t, sometimes called "onion" because you can repeat it for layers.

8.4A box, derived from scratch

Circles are easy because every edge point is the same distance from the center. A rectangle has flat sides and sharp corners, so the nearest edge point depends on where you are. Let's build its SDF step by step, for a box centered at the origin with half-width b.x and half-height b.y.

Step 1: fold. The box is symmetrical, so the answer for (−3, 2) is the same as for (3, 2). abs(p) folds all four quarters onto the top-right one (the mirror trick from Chapter 4), and now there's only one corner to think about.

Step 2: measure past the edges. q = abs(p) - b. q.x is how far you are to the right of the right edge's line (negative if you're to its left), and q.y is how far above the top edge's line.

Step 3: look at the regions.

  • To the right (q.x > 0, q.y < 0): the nearest point is straight left, on the right edge. Distance = q.x.
  • Above (q.y > 0, q.x < 0): straight down to the top edge. Distance = q.y.
  • Diagonally past the corner (both positive): the nearest point is the corner itself, and q is exactly the arrow from the corner to you. Distance = length(q).
  • Inside (both negative): the nearest edge is whichever is closer, the one whose gap is smaller. The distances to the edges are −q.x and −q.y, so the nearest is −max(q.x, q.y) away, and since we're inside, the signed distance is max(q.x, q.y), a negative number.

Step 4: one formula for all four. max(q, 0.0) zeroes out any negative part, so length(max(q, 0.0)) gives q.x, q.y or length(q) in the three outside regions, and 0 inside. And min(max(q.x, q.y), 0.0) is the inside answer, and 0 outside. Add them:

float sdBox(vec2 p, vec2 b) {
    vec2 q = abs(p) - b;
    return length(max(q, 0.0)) + min(max(q.x, q.y), 0.0);
}

Here it is in the field view, with its corners rounded by subtracting r (and shrinking the box by r first so its size stays the same). The circle around your pointer has a radius equal to the distance at its center, so it always just touches the box. Drag on the canvas to move it:

Watch the bands outside the corners: they're round, because past a corner the nearest point is the corner. Inside, the bands are boxes with mitered (diagonal-cut) corners. The probe circle is a promise: nothing is closer than this. Chapter 13 turns that promise into 3D rendering.

8.5A line segment, by projection

Chapter 7's projection gives the distance to a segment from a to b. The idea: find the point on the segment closest to p, then measure the distance to it.

  1. pa = p - a is the arrow from a to p, and ba = b - a is the segment itself.
  2. How far along the segment is p's shadow? Project: dot(pa, ba) / dot(ba, ba). This is 0 at a and 1 at b. (Dividing by dot(ba, ba), the squared length, both normalizes and converts to "fraction of the segment" in one go.)
  3. Clamp that to 0..1 so the closest point can't run past either end.
  4. The closest point is a + ba * h, and p's distance from it is length(pa - ba * h).
float sdSegment(vec2 p, vec2 a, vec2 b) {
    vec2 pa = p - a, ba = b - a;
    float h = clamp(dot(pa, ba) / dot(ba, ba), 0.0, 1.0);   // 0 at a, 1 at b
    return length(pa - ba * h);
}

This is an unsigned distance (a segment has no inside), but subtracting a thickness turns it into a solid capsule with rounded ends. Segments and circles are enough for a working clock, reading your computer's time from the uniform iDate:

Notice min combining the hour and minute hands into one shape. That's the next section.

8.6Combining shapes: min, max and minus

Because SDFs are just numbers, combining shapes is arithmetic. Say d1 and d2 are the distances to two shapes:

  • Union (either shape): min(d1, d2). The distance to the pair is the distance to whichever is nearer.
  • Intersection (only where they overlap): max(d1, d2). You're inside only if both distances are negative, which means the larger one is negative.
  • Subtraction (shape 1 with shape 2 cut out): max(d1, -d2). Negating d2 swaps its inside and outside, so this is "inside shape 1 and outside shape 2".
Not quite exact any more

After max or subtraction, the result is still negative inside and positive outside, so it draws perfectly. But some of its values (look at the bands inside the intersection) are no longer the true distance; they can be smaller. That's called a bound: it never overestimates. For drawing it doesn't matter, and for 3D in Chapter 13 a bound is still safe, because a step of that size never overshoots.

8.7Melting shapes together: smooth minimum

min joins two shapes with a sharp crease where they meet. A smooth minimum blends them instead, adding material in the crease so the shapes flow together like drops of liquid:

float smin(float a, float b, float k) {
    float h = clamp(0.5 + 0.5 * (b - a) / k, 0.0, 1.0);
    return mix(b, a, h) - k * h * (1.0 - h);
}
Math from zero: how smin works

k is the blending distance. Look at h: when a is smaller than b by more than k, h is clamped to 1 and the result is mix(b, a, 1) - 0 = a, the ordinary min. When b is smaller by more than k, h is 0 and you get b. So far from the meeting point, smin is exactly min.

When a and b are within k of each other, which happens near where the shapes meet, h is in between: mix blends the two distances, and k * h * (1 - h), a small hump that peaks at h = 0.5 (where a = b), pulls the result lower. A lower distance means "more inside", so material appears in the crease.

What happens with k = 0.0? And with a much bigger k, like 0.5?

With k = 0 the formula divides by zero, so it's undefined (use plain min for no blending). A tiny k like 0.01 gives separate circles with sharp creases where they touch. A big k like 0.5 makes the blobs reach for each other from far away, and the whole group swells into one soft mass, because smin always subtracts a little, which grows every shape.

// AHA

Shapes are numbers, so modeling is arithmetic: min joins, max intersects, minus cuts, smin melts. The same four operations build the 3D scenes in Part II.

8.8When you don't know how big a pixel is

All the edges above used px = 2.0 / iResolution.y, which is right as long as you haven't zoomed or warped the coordinates. After you scale space (Chapter 9) or bend it (Chapters 10 and 11), one pixel might be a much bigger or smaller step in distance. The GPU can measure it for you: fwidth(d) tells you how much d changes from this pixel to its neighbors. Then:

float w = fwidth(d);                         // how much d changes across one pixel
float fill = 1.0 - smoothstep(-w, w, d);     // a crisp edge at any zoom

How can one pixel know about its neighbors' values? The GPU runs pixels in little 2 × 2 groups in lockstep, and can compare their values directly. Chapter 17 explains.

What you now know

  • Yes/no tests make jagged edges (aliasing). A distance lets you estimate coverage: 1.0 - smoothstep(-px, px, d).
  • A signed distance function returns: positive outside, zero on the edge, negative inside. Circle: length(p) - r.
  • One distance gives fill, outline (abs(d) - t), glow (k / abs(d)), ripples (fract(d * n)) and rounding (d - r).
  • Box: fold with abs, measure past the edges with q = abs(p) - b, then handle the corner, edge and inside cases.
  • Segment: project onto it, clamp to the ends, measure to the closest point.
  • Union = min, intersection = max, subtraction = max(d1, -d2), melting = smin.
  • fwidth(d) measures a pixel in distance units, for crisp edges at any zoom.
