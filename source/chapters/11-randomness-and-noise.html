A shader can't roll dice, and it can't remember what it rolled last frame. Yet shaders are full of organic randomness: clouds, marble, wood, fire, cells. All of it comes from one strange-looking line of code, a hash, plus the blending ideas you already know. This chapter builds the whole family from that line up.

Randomness without memory: hash functions

In p5.js, random() gives a different number every call. A shader can't work like that. If each pixel picked a new random number every frame, the picture would flicker like TV static. And there's no way to store a number and reuse it next frame (until Chapter 15).

The solution is to make randomness a function: feed in a position, get back a number that looks random but is always the same for the same input. Such a function is called a hash. Here's the classic one, which you'll find in thousands of shaders:

It looks like magic numbers, but each step has a job:

  1. dot(p, vec2(127.1, 311.7)) squashes the two numbers into one, mixing x and y with very different weights so that, say, (1, 2) and (2, 1) don't give the same result.
  2. sin(…) turns that into a smoothly wiggling number between −1 and 1.
  3. * 43758.5453 blows it up enormously. A tiny change in the input now becomes a big change in the output.
  4. fract(…) keeps only the digits after the decimal point. Those digits change so fast with the input that neighboring inputs give unrelated-looking answers.

You can watch this happen. The plot below shows fract(sin(x) * k). With a small k it's clearly a wave. Turn k up, and the wave wiggles faster than the pixels can follow, until neighboring pixels land on unrelated heights and it looks like noise:

It isn't truly random: it's a perfectly predictable formula. That's exactly what makes it useful. Same input, same output, so the randomness holds still from frame to frame. The specific numbers don't matter much; they just need to be "unrelated" enough that no pattern shows. (This sine-based hash can show faint patterns on some GPUs at very large inputs. If that ever bites you, search for "hash without sine" by Dave Hoskins for a sturdier drop-in.)

Random choices: Truchet tiles

A random number can make a choice. In 1704, the priest Sébastien Truchet studied tiles that can be laid in different orientations. Here's a modern version: each tile holds two quarter-circle arcs linking the midpoints of its edges. A hash flips half the tiles at random, and the arcs join up across tiles into an endless maze:

Change hash(id) < 0.5 to hash(id) < 0.0 (never flip). What do you get?

Perfectly regular rows of waves. The maze only appears when neighboring tiles disagree: the randomness isn't creating the paths, it's breaking the symmetry of a pattern that was already there. A lot of generative art works this way: a strict system, plus a little controlled randomness.

Smooth randomness: value noise

A hash per tile gives blocky randomness: every tile is a flat, unrelated color. Nature isn't blocky. Clouds and hills are random, but smoothly random: nearby points have similar values. That's what noise means in graphics: randomness with no sharp jumps.

The simplest way to get it: put a random value at every grid corner, and for each point inside a tile, blend the values of its four surrounding corners. Blend along x on the bottom edge and on the top edge, then blend those two results along y. This is called bilinear interpolation, and it's just three mix calls:

The widget shows why one detail matters. A straight blend (mix with t = f) is smooth inside each tile, but the slope changes suddenly at tile edges, which shows up as visible creases along the grid. Blending with f * f * (3 - 2 * f) instead, which is the curve inside smoothstep, starts and ends flat, so neighboring tiles meet without a crease.

Better noise: gradients instead of heights

Value noise has a tell: its hills and valleys tend to sit on the grid, because the extremes are always at the corners. In 1983, after working on the film Tron and growing tired of how machine-like computer graphics looked, Ken Perlin found a better idea. It later won him an Academy Award. Instead of a random height at each corner, give each corner a random slope: a direction in which it rises.

Each corner then contributes a tilted plane: zero at the corner itself, going up in its random direction and down the other way. "How high is that plane at this point?" is a dot product (Chapter 7) of the corner's direction with the arrow from the corner to the point. Blend the four planes with the same smooth curve, and the result is gradient noise (Perlin's version is called Perlin noise):

On the left, light and dark blobs cluster at grid corners. On the right, the features fall anywhere, and the gradient noise is exactly 0.5 (mid-grey) at every corner, because each plane is zero at its own corner. Both are used everywhere; gradient noise usually looks more natural.

Nature is fractal: fBm

Look at a coastline on a map. It has big bays. Zoom in on one bay, and its edge has smaller coves. Zoom into a cove, and there are rocks with even smaller wiggles. Mountains, clouds and bark all have this property: detail at every scale, each smaller scale weaker than the one above. Things like this are called fractal.

Noise has detail at only one scale, set by the grid size. To fake nature, add several layers of noise, called octaves (the word comes from music, where each octave doubles the frequency). Each octave has twice the frequency and half the amplitude of the one before:

This is fractal Brownian motion, fBm for short (the name comes from physics; don't worry about it). Big shapes from the first octave, medium bumps from the next, fine grain from the last. It's the most-used trick in procedural graphics:

What do you expect with only 1 octave? And what if amp *= 0.5 becomes amp *= 0.8?

One octave is plain value noise: soft, smooth, unconvincing blobs. With a gain of 0.8, the small octaves stay almost as strong as the big ones, so the clouds become rough and grainy, like rock or static. A gain of 0.5 is the classic natural-looking balance.

Noise as an ingredient

Noise rarely appears raw. Usually it nudges something else. Wood is rings (Chapter 10's distance from a center) pushed around by noise; marble is stripes (a sine wave) pushed around by fBm:

Domain warping: noise feeding noise

The marble used fBm to push the input of another function. Take that idea all the way: push the input of fBm with fBm itself. Instead of asking for fbm(p), ask for fbm(p + fbm(p)). The inner fBm shoves each pixel's lookup somewhere else, so straight features bend and swirl. Do it twice and you get smoke and marbled paper. The offsets like vec2(5.2, 1.3) just make the two parts of q look up different, unrelated stretches of noise, so they don't move in lockstep. And q, r and f don't only shape the picture: they're three different smoothly varying numbers at every pixel, which is why they make such rich color inputs.

Noise is smooth randomness. Its real power is as an ingredient: add octaves for detail, use it to push around the input of another pattern, or feed it to itself. Everything organic is a few lines on top of one hash.

Cells: Voronoi

Back in Chapter 7, two points split the canvas into two regions by which one is closer. Scatter many points and the regions become a mosaic of cells, like soap bubbles, giraffe spots, cracked mud or leaf cells. This is a Voronoi diagram (also called cellular or Worley noise).

Checking every point for every pixel would be slow. The trick: put exactly one random point in each tile of a grid. Then a pixel's nearest point is almost always in its own tile or one of the eight around it, so each pixel checks only those nine:

Three things to read from the result:

  • d1, the distance to the nearest point, makes soft bubbles around each point.
  • The id of the nearest point gives each cell a flat random color.
  • d2 − d1 is small exactly where two points are almost equally near, which is the border between their cells. That's how the dark cracks are drawn.

What you now know

  • A hash is a function that scrambles its input into a random-looking 0..1 number. Same input, same output, so nothing flickers.
  • What you feed the hash decides what's random: per tile (floor), per second (floor(iTime)), per pixel.
  • Value noise: random values at grid corners, blended with f * f * (3 - 2f). Gradient noise: random slopes at corners, which looks more natural.
  • fBm: add octaves, each double the frequency and half the amplitude. Nature's detail-at-every-scale.
  • Noise is an ingredient: it bends stripes into marble and rings into wood. Domain warping feeds fBm into itself.
  • Voronoi: one random point per tile, check the 3 × 3 neighborhood, use d1, the id, or d2 − d1.
